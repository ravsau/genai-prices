## Things I was unsure about or guessed at (must be confirmed)

1. **Catch-all `codex-subscription` entry could NOT be added — omitted.** The packet asks for a final
   catch-all with `match: {starts_with: gpt-}`. `make build` rejects it: the validator asserts no model
   matches another model's `id`, and `starts_with: gpt-` overlaps every `gpt-5.x-codex` entry:
   ```
   1 validation error for Provider
   models
     Assertion failed, Model `gpt-5-codex` matches other model ids: ['codex-subscription'] [type=assertion_error, ...]
   ```
   The planner's reading is not buildable together with the one-entry-per-codex-model requirement, so the
   exact entries (which cover every current Codex id) stay and the catch-all is dropped. This is a
   deviation from the packet text; a maintainer may want to revisit.
2. **`prices: {}` instead of "NO `prices:` key".** `ModelInfo.prices` is a required field
   (`prices/src/prices/prices_types.py:193`, no default; also required in `.schema.json`), so "no prices
   key at all" fails build/validation. An empty `{}` parses to a `ModelPrice` with every field unset,
   which is exactly what `is_free()` checks (prices_types.py:279-287), giving the intended free/zero-cost
   behavior. So `prices: {}` is the correct machine representation of "no per-token price".
3. **`api_pattern` and `pricing_urls` are UNVERIFIED** — copied from the packet's planner best reading
   (`https://chatgpt\.com/backend-api/codex` and `https://developers.openai.com/codex/pricing`) and should
   be confirmed by the maintainer; I had no way to test the API pattern and did not make network calls
   beyond git/uv.
4. Model ids and `prices_checked: 2026-09-05` were taken from `openai.yml` on this checkout; `codex-mini`
   also matches `codex-mini-latest` upstream but that is an alias of the same canonical id and is covered
   by the `codex-mini` entry's `equals` match in the API (it is a different id string, so the exact-entry
   list follows the packet's "one per Codex model id" instruction).
5. Two commits on the branch: the feature commit (2de62b1) from the earlier session and a follow-up
   commit for the regenerated `tests/dataset/usages.json` (8843364). No pre-commit hooks are installed in
   this box (only `.git/hooks/*.sample`), so `make build` was run manually before committing.
